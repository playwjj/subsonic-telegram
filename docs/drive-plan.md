# Web UI 音乐库管理升级计划（网盘化）

> 状态：P0、P1、P3 已实现（2026-10-16）。分析基于当天的代码（`651a725`）和生产 D1 数据。
> 已定：替换 Folders 页；删除默认进回收站（P3 实现前仍为永久删除）；「改文件名」和「编辑标签」分开。

与原计划的出入：
- LIKE 转义改成了用 `[prefix + "/", prefix + "0")` 区间匹配，不需要转义，还能用上索引，并且区分大小写。
- 重名冲突只提供「两个都保留（自动改名）」和「跳过」，没有单独的「保留同名」。
- 单个文件夹最多 345 首，所以没有做分页和虚拟滚动。
- Telegram 删除改用 `deleteMessages` 批量删除，每次 100 条，避免撞上 Worker 子请求数上限。
- P3：快照不是存成一整段 JSON，而是按行存在 `trash_rows` 表里（单行 JSON 最大 2MB，3000 首的文件夹放不下）。删除不弹确认框，改为提示条上提供「撤销」；「永久删除」保留确认框。

## 一、现状

### 已有的管理功能

`web/src/views/FoldersView.vue` + `src/index.ts` 里的几个自定义接口：

- 文件夹是从 `tracks.source_path` 推出来的，另外有一张 `folders` 表专门记录空文件夹。
- 能做的操作：单首上传（一次只能一个文件）、单首删除（直接永久删，同时删 Telegram 消息）、新建文件夹、文件夹改名（只能改最后一段）、删除空文件夹。
- 没有的：多选、批量操作、移动、编辑标签、回收站、上传进度、存储统计、文件属性面板。

### 生产库现在的样子

- 4503 首歌，约 39.5GB，全部都有 `source_path`，最深 3 层，共 57 个叶子文件夹。
- 最大的 `经典歌曲3000首` 下有 3019 首，单个叶子文件夹最多 345 首。
- 按「标题+艺人」算，有 245 组疑似重复。

### 发现的问题

1. **`getFolder` 有性能问题**。它会把路径下面所有层级的歌全部查出来，再在内存里算出子目录。打开根目录要读 4503 行（还带 join），打开「经典歌曲3000首」要读 3019 行，只为了显示十几个子文件夹。
2. **LIKE 没有转义**。`listTracksUnderPath` 直接拼 `${prefix}/%`，文件夹名里如果有 `_` 或 `%` 会匹配到别的文件夹。改名、删除、随机播放都用这个函数，后面做批量移动和删除时会变成真正的 bug。
3. **删除是永久且不能撤销的**。D1 那边是级联删除，Telegram 消息删失败时只打一条日志，留下一个孤儿消息。
4. **没有改元数据的接口**。标签写错了只能删掉重传。
5. **`download` 没有返回 `Content-Disposition`**，浏览器下载下来的文件名不对。
6. **所有接口只读 URL 里的参数**，批量操作时几百个 id 放进 URL 会超长。

还有一个约束：Telegram Bot API **没法列出频道里的历史消息**，所以 D1 是唯一的索引。一旦 D1 出问题，Telegram 里的文件就对不上号了。网盘化之后，这个单点风险要一起处理。

## 三、分阶段计划

### P0 后端打底（小，其它阶段都依赖它）

- **加一个 `dir` 列并建索引**。可以用 SQLite 的虚拟生成列：`ALTER TABLE tracks ADD COLUMN dir TEXT GENERATED ALWAYS AS (...) VIRTUAL`，从 `source_path` 算出来，不用迁移数据。如果 D1 的 ALTER 不支持，就改成普通列，写入时由代码维护。
- **重写 `getFolder`**：
  - 当前目录下的歌用 `WHERE dir = ?` 查，配合分页。
  - 子目录用一条 `GROUP BY` 查出来，同时返回每个子目录的歌曲数、总大小、总时长（网盘里文件夹那一行要显示这些）。
- **统一给 LIKE 加转义**（`ESCAPE '\'`）。
- **支持 POST 表单传参**，也就是 OpenSubsonic 的 `formPost` 扩展：把请求体的参数合进 `params`。批量接口靠它，第三方客户端也能用。
- **`download` 加 `Content-Disposition`**，下载时用原始文件名。

### P1 文件管理核心（大，主体工作）

后端新增接口：

| 接口 | 作用 |
|---|---|
| `moveItems(id[], path[], dest)` | 把歌和文件夹（整棵子树）移到另一个目录，用一个 `db.batch` 完成 |
| `renameTrackFile(id, name)` | 只改文件名（`source_path` 最后一段），不动标签 |
| `deleteItems(id[], path[])` | 批量删除，支持递归删文件夹（P3 之后改成进回收站） |
| `getFolderTree()` | 只返回目录结构（57 个节点），给左侧树用 |
| `searchInFolder(path, q)` | 在当前目录及子目录里搜索 |

前端：

- 新的 `DriveView`，替换 Folders 页，路由沿用 `/folders/*`。表格有多列，可以排序，大目录用虚拟滚动；也可以切换成带封面的网格视图。
- **选择方式**：复选框、Shift 连选、Ctrl/⌘ 多选、全选；手机上长按进入多选。
- **选中后的操作**：顶部浮出操作栏，加上右键菜单。播放、加入队列、加到歌单直接复用现有组件。
- **拖拽**：把选中的行拖到左侧树或面包屑上就是移动。
- **键盘**：Delete 删除，F2 改名，Enter 播放，Backspace 返回上级，Ctrl+A 全选。
- **属性面板**：完整路径、大小、码率、添加时间、播放次数、Telegram 消息链接（`t.me/c/<频道>/<消息id>`），以及是否已缓存到 R2。
- **重名冲突**：目标目录里已有同名文件时，弹窗让用户选「自动改名为 xxx (1).mp3」「跳过」或「两个都保留」。
- 「移动到…」用一个文件夹选择弹窗。

### P2 上传体验（中）

- 支持一次选多个文件，也支持把整个文件夹拖进来（用 `webkitGetAsEntry`），**保留原来的目录结构**。
- 做一个全局上传队列（放在 store 里），右下角浮动面板显示每个文件的进度（用 XHR 的上传进度事件）。切换页面不会中断上传。
- 并发控制在 1–2 个。Telegram 往同一个频道发消息大约限速 20 条/分钟，所以后端要把 429 和 `retry_after` 透传给前端，前端自动等待后重试。100 首大约要 5 分钟，界面上要说明这一点。
- 标签直接用浏览器解析出来的结果，不再每首弹表单。上传前可以统一改专辑或艺人。超过 19MB 和格式不支持的文件提前标红跳过。
- 上传前检查重复：目标目录里有同名同大小的文件就提示。
- 不填文件夹时，默认放进 `上传/2026-10`，避免歌曲在 Folders 里看不到。

### P3 回收站（中，强烈建议做）

- 新建一张 `trash` 表，删除时把这首歌的完整快照（track 行、所属专辑和艺人行、它在哪些歌单的哪个位置、收藏记录）存成 JSON，再删掉原来的行。
  - 这样做的好处是现有约 20 处用到 `TRACK_SELECT` 的查询**都不用改**。如果改成在 tracks 表加 `deleted_at`，每处查询都得加过滤条件，很容易漏。
- 回收站页面：还原（会重建被一起删掉的专辑和艺人，并放回原来的歌单位置）、彻底删除、清空。
- **这时才删 Telegram 消息**。删失败的记下来，后面重试，而不是悄悄留下孤儿消息。
- 用 Cron Trigger 每天自动清理超过 30 天的条目。

### P4 元数据管理（中）

- `updateTracks(id[], 字段…)`：单首或批量修改标题、艺人、专辑、年份、流派、曲目号、碟号。
  - 会自动建新的艺人和专辑，并清理因此变空的旧专辑和旧艺人（复用 `deleteTrackCascade` 里的清理逻辑）。
  - **歌曲 id 保持不变**，所以收藏、歌单、播放队列都不受影响。
- 上传或替换专辑封面：走 `putFile`，再写入 `cover_ref`。
- **重复文件查找页**：按「标题+艺人+时长」或者按大小分组，逐组勾选要删的那些（删除会进回收站）。目前就有 245 组可以处理。

### P5 存储与可靠性（中）

- **存储空间页**：总用量、各顶层文件夹占用、格式分布、R2 缓存用量与上限。
- **D1 元数据备份**：用 Cron 定时把整库导出成 JSON（压缩后），用 `sendDocument` 发到 Telegram 频道并置顶。D1 出问题时可以用它恢复。这是让 Telegram 当网盘最关键的一项。
- **上传时给 Telegram 消息加 caption**（文件路径 + 歌曲 id），移动或改名时用 `editMessageCaption` 同步。这样频道本身也能看懂，可以作为第二道恢复手段。
- **完整性检查**：分批对文件调用 `getFile`，标出失效的文件。
- 可选：实现 `getMusicDirectory`，让 DSub、Ultrasonic 这类第三方客户端也能按文件夹浏览。
